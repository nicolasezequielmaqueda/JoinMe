**Team:** Nico & Jaime

> Labels used in this document: **[E]** = evidence from a source or observation, **[A]** = assumption that we have not verified yet.

---

## 1. Project canvas

| Field | Content |
|---|---|
| **User** | Adult Erasmus / international student who recently moved into a student residence. |
| **Task** | Do a simple shared activity (table tennis, football, board games, movie night…) in the residence. |
| **Barrier** | The facilities exist, but the student does not know who is free and interested at the same time, so the activity does not happen. |
| **Solution** | An activity-first app: create an activity (what, when, where, how many people) or join one that already exists. No profiles, no chat. |
| **Core value** | "Find something to do together, rather than searching for people to meet." |
| **Main journey** | Activities → Activity Detail → Join → activity appears in My Activities. |
| **Platform** | Android (primary), iOS from the same shared code. |
| **Success signal** | A first-time user finds and joins an activity without help (see task criterion in section 3). |

## 2. Evidence and assumptions

**Problem evidence**

- **[E]** Research on international students reports loneliness and difficulty building new social connections after moving abroad (e.g. Sawir et al., 2008, *Loneliness and International Students: An Australian Study*, Journal of Studies in International Education, 12(2)).
- **[E]** Anonymous observation (team, Erasmus residence, October 2026): *TODO – describe one short anonymous situation you observed, e.g. "a shared table / court was unused most evenings while students in the group chat asked if anyone wanted to play". No names or personal data.*

**Assumptions (to be checked in the usability sessions)**

- **[A1]** Students are more willing to join a concrete activity than to message a stranger directly.
- **[A2]** Most activities happen inside the residence, so a predefined list of places is enough (no GPS needed).
- **[A3]** A short list of predefined activity types covers most cases; "Other" covers the rest.
- **[A4]** Users will open the app themselves to look for activities; reminders are helpful but not essential.

**What we do not claim:** JoinMe does not solve loneliness, improve mental health or guarantee friendships. It only tries to remove one practical barrier: finding people for the same activity at the same time.

## 3. Scope and acceptance criteria

### User stories

**US1 – Discover.** *As an Erasmus student, I want to see the available activities so that I can find something to do with other students.*
- Given there are activities, when I open the app, then I see a list where each card shows type, date/time, location, participants (e.g. `1 / 2`) and a status written as text (`OPEN`, `FULL`).
- When I select a filter (All, Sports, Games, Social, Today), only matching activities are shown.
- If no activity matches, a clear empty message is shown instead of a blank screen.

**US2 – Join.** *As an Erasmus student, I want to join an activity so that I can participate without already knowing the other participants.*
- Given an `OPEN` activity, when I press **Join**, the participant count increases by one and the button changes to **Leave**.
- If the activity reaches its maximum, its status changes to `FULL` and nobody else can join.
- The joined activity appears in **My Activities → Joined**.

**US3 – Create.** *As an Erasmus student, I want to create an activity with when, where and how many people are needed so that other students can join me.*
- I can choose type, date, start time, duration, location, maximum participants (2–30) and an optional description.
- The **Create** button is disabled and a message is shown if a required field is missing or the date is in the past.
- After creating it, the activity appears in **Activities** and in **My Activities → Created** with `1 / N – OPEN` (the creator counts as the first participant).

### Core journey and measurable task criterion

**Open JoinMe → Activities → Table Tennis → Detail → Join → `1/2` becomes `2/2 FULL` → My Activities**

Task criterion: in the usability sessions, a first-time participant can **find and join a given activity in under 60 seconds and with no more than 5 taps, without help**, and **create a new activity in under 2 minutes**.

### Explicit exclusions (out of scope)

Chat and private messages, friends/followers, social profiles, photos and camera, GPS and maps, payments, ratings/reviews/likes, AI recommendations or matching, complex authentication, continuous tracking.

## 4. Prototype

The prototype is **real code**, not a Figma mock-up: a Compose Multiplatform app with real navigation, reusable UI components and in-memory sample activities. The same code will become the M2 application (Room and Supabase are added later behind the repository layer).

| Screen | What it shows in M1 |
|---|---|
| **Activities** | Today's date, filters (All, Today, Sports, Games, Social) and activity cards with time, place, a capacity bar, `x of y people` and a text status (`OPEN`, `FULL`). "+ New" opens the form. |
| **Activity Detail** | Activity header, people section ("1 spot left"), details (date, time, duration, place, category), notes and one main action at the bottom: Join, Leave or Cancel (with confirmation). |
| **Create Activity** | Grid of predefined activity types, date and time pickers, duration, predefined places, a stepper for people (2–30) and optional notes. The button is disabled and a hint explains what is missing until the form is valid. |
| **My Activities** | Upcoming / Past switch, split into "Created by you" and "Joined". |

**Visual design.** Calm, iOS-inspired interface: light grey background, white rounded cards and a single muted blue accent. Each category has one soft colour (sports = sage, games = sand, social = lavender, other = blue grey), so users learn to recognise it. Icons come from the open-source Phosphor set, and the font is Inter.

## 5. Accessibility requirements

1. **Scalable text.** The whole core journey must remain usable with the system font size set to the largest value: no text cut off, no buttons hidden. *Test:* repeat the core journey with the largest Android font size.
2. **Information never depends only on colour.** Every status is written as text (`OPEN`, `FULL`, `JOINED`, `CANCELLED`, `COMPLETED`); colour only reinforces it. *Test:* check every screen in greyscale mode; the status must still be readable.

Additionally, every button and icon has a content description and touch targets are at least 48 × 48 dp.

## 6. Initial data and risk inventory

**Data**

| Data | Purpose | Where (final app) | Sensitivity |
|---|---|---|---|
| Activity (type, date/time, duration, location, max participants, description) | Show and join activities | Supabase + Room copy | Low – no personal data |
| Technical user ID (random) | Know who created / joined an activity | Device + Supabase | Low – not linked to a real name |
| Participation (user ID ↔ activity ID) | Participant count, My Activities | Supabase + Room copy | Low |
| Notification permission | Activity reminders | Device only | Low – optional |

Not collected: real names, photos, contact data, precise location, health or financial data. M1 uses only synthetic data. No personal interview data is stored in the repository.

**Risks and mitigations**

| Risk | Mitigation |
|---|---|
| Meeting strangers (safety) | Only shared, public residence places can be selected; no private addresses. |
| Free-text description reveals personal data | Short length limit and a hint "do not include personal information". |
| Fake or spam activities | Out of scope for the MVP; noted as a limitation. Creator can cancel their own activity. |
| Offline / stale data | Show saved activities with the message "You're offline. Showing saved activities." |
| Notifications denied | App remains fully usable; reminder is optional. |
| Scope creep | Explicit exclusions list (section 3); one polished flow first. |
| iOS build needs macOS | Android is the primary target; iOS is built later on a Mac. |
